# 场景应用接入交接

用户端和管理端都调用平台 API。业务流程已提供模拟实现：手工/工具链发布、审批、版本、范围、体验、互动、通知、配置。当前没有创建场景应用数据库表或迁移，也没有调用供应方实际服务。

### 存储

内存事务当前整体提交/回滚。真实仓储必须让审核记录、申请状态、版本、目录和通知一起提交。revision不一致返回409。并发控制应使用数据库事务和唯一约束，不能照搬进程内锁或全量复制。

后续表关系起点：应用→版本；版本→资源依赖；申请→应用/版本；申请→审核快照与评分；应用→开放范围；用户×应用→收藏/订阅/评分；用户×应用×请求编号→调用与下载记录；供应方×工作空间×外部编号→来源绑定；同步任务→申请；通知→接收人/应用；配置→修订号。先确认公共用户组织编号与HiMarket目录/审批归属，再定最终表结构。本轮未建表。

`ApplicationSession.entries/entry/put_entry` 暂存互动、运行、同步、绑定、通知和配置。数据库实现宜转为有索引的领域查询；当前全量筛选仅适合演示。

### 供应方

需要对方给可达环境地址、鉴权/测试授权、工作空间及应用/版本编号、请求响应样例、错误码、运行输入输出和同步规则。密钥保留在后端。URL替换只是配置的一部分，还需字段映射和实际联调。

当前Provider合同：`dependencies`、`validate_dependencies`、`toolchain_resources`、`toolchain_resource`、`develop`、`invoke`、`runtime_status`。`develop`是本地工具链演练，真实开发可直接跳到配置的供应方工作空间，无需自行重建编排工具。真实版本、环境和工作空间绑定要扩展当前demo-toolchain绑定键。

运行采用requestId幂等：同一账号/应用/请求相同输入沿用记录，不同输入409；重新发起生成新编号。同步任务同一requestId去重，同一外部版本沿用申请；已有待处理版本时不覆盖。失败保留记录。真实异步任务需补任务轮询/回调、超时恢复、进程退出后的running状态恢复和供应方幂等支持；当前模拟调用同步完成。

下载目前导出应用资料JSON，不是可执行程序包。使用次数是成功模拟调用数，收藏按账号去重，评分每人保留一份；响应时间/成功率仅计算实际执行过的模拟调用。初始目录统计是样例，没有真实数据时不虚构正式性能。

### 身份与开放范围

`AUTH_MODE=disabled` 使用仅开发的预置身份，用户端/管理端分别保存HttpOnly演示Cookie。它不是生产认证。启用同事的模拟IAM后，公共认证依赖先验证用户/管理会话和CSRF，再给场景模块可信身份；演示切换被禁止。管理身份来自管理端已授权会话，普通会话不能通过浏览器传角色升权。

当前IAM返回用户编号和姓名，没有组织/项目归属。适配器给普通登录用户发布自己应用的权限，管理准入沿用公共模块；缺少的组织/项目为空，不能访问指定组织/项目的资源。正式IAM需对接对应目录与角色规则。不要用演示组织填充真实用户。

范围检查覆盖目录搜索、详情、个人互动、资料下载、调用、申请读写与审核。正式关联资源目录还需各模块的权限合同。服务器工作流通知为站内消息，未接邮件/短信。

## 启动与验证

用户端默认5173，管理端5174，平台后端8000；使用同一后端单实例与一个worker。热重载/重启清空场景记录。用户端离线Mock保留原资料流程，新增跨端工作流需HTTP模式。

- Server：`.venv/Scripts/python.exe -m pytest -q`、`.venv/Scripts/ruff.exe check app tests`。
- User：`pnpm test --run`、`pnpm build`。
- Admin：`npm run build`、`npm run test:e2e`。跨端测试自动启动相邻User/Server，端口8018/4183/4184并明确关闭认证，不写入人工演示实例。

数据库、Redis/共享缓存、文件服务、生产登录和双实例部署仍在后续阶段；认证框架自己的测试数据库属于已有公共模块，场景模块未新增SQL模型或迁移。
