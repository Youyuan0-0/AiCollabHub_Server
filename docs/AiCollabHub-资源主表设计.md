# AiCollabHub 资源主表设计

确认日期：2026-09-20。

状态：数据集与场景应用主表设计已确认，本文件不表示数据库已建表或业务代码已完成迁移。命名与通用约束见 [代码规范](AiCollabHub-代码规范.md) 的“资源主表设计”。

## 设计边界

五类资源各自维护主表：`datasets`、`models`、`applications`、`knowledge_bases`、`ai_tools`，不在模块主表中增加 `resource_type`。本次仅定稿 `datasets` 与 `applications`；其他三张表的专属字段继续按实际页面和数据来源确认。

主表保存资源基本资料和当前正式展示的概览内容。发布申请承接草稿与待审核资料；版本、用户互动、关联资源和外部状态按各自来源组合成详情响应。前端展示一个字段，不等于主表必须保存同名列。

以下类型按 PostgreSQL 设计。“可空”允许 SQL `NULL`；字符串数组使用 JSONB，默认 `[]`，校验为字符串元素并去空、去重。业务必填规则在发布校验中落实，具体 SQL 约束在落库时同步实现。

## 数据集主表 datasets

业务定位：保存一个数据集的稳定标识、当前正式展示资料、当前版本关联和启用状态。

| 字段名 | 中文名称 | 类型 | 业务逻辑 / 枚举值 / 备注 |
| --- | --- | --- | --- |
| `id` | 数据集编号 | `uuid` | 主键；平台生成，版本更新时保持不变。 |
| `name` | 数据集名称 | `varchar(200)` | 必填；用于列表、搜索和详情标题，不要求全局唯一。 |
| `english_name` | 英文名称 | `varchar(200)` | 可空。 |
| `summary` | 数据集简介 | `text` | 必填；用于列表摘要和概览开头。 |
| `description_markdown` | 详细说明 | `text` | 必填；保存 Markdown 正文。 |
| `provider_name` | 所属单位 | `varchar(200)` | 必填；提供数据集的单位名称，与创建人分开。 |
| `contact` | 联系人 | `varchar(200)` | 保存发布资料中的联系人姓名，不混存联系电话、邮箱等联系渠道。 |
| `tags` | 关键词标签 | `jsonb` | 字符串数组，默认 `[]`。 |
| `task_types` | 任务类型 | `jsonb` | 字符串数组，默认 `[]`；支持多个任务类型。 |
| `data_applications` | 数据应用 | `jsonb` | 字符串数组，默认 `[]`；如智能研发、智能制造等。 |
| `data_shapes` | 数据形态 | `jsonb` | 字符串数组，默认 `[]`；如文本、图像、结构化数据等。 |
| `ai_purpose` | AI 应用目的 | `varchar(64)` | 沿用当前单选；如预训练、微调、评测、知识库，选项按字典维护。 |
| `update_frequency` | 更新频率 | `varchar(100)` | 可空；如每月更新、不定期更新。 |
| `record_count` | 数据记录数 | `bigint` | 可空且非负；当前版本的数据规模，未知时为空，不填成 0。 |
| `data_size_bytes` | 数据大小 | `bigint` | 可空且非负；按字节保存，页面转换为 MB、GB 等。 |
| `creator_id` | 创建人编号 | `uuid` | 关联 `users.id`；本地发布时必填，外部同步资源可空，不伪造创建人。 |
| `current_version_id` | 当前版本编号 | `uuid` | 关联数据集版本记录；指向当前正式展示的版本，关联建立前可空。 |
| `status` | 状态 | `varchar(16)` | `enabled` 启用、`disabled` 禁用；默认 `disabled`，不表示审核状态。 |
| `created_at` | 创建时间 | `timestamptz` | 本平台创建这条主表记录的时间。 |
| `updated_at` | 更新时间 | `timestamptz` | 主表资料或启用状态发生变化时更新。 |

`record_count`、`data_size_bytes` 保存当前版本的规模资料，可以来自发布资料或工具链同步的快照。必须对应同一当前版本，不能拿未审核的新版本数据覆盖已公开版本的数据规模。具体来源和更新路径随对接协议落实。

字段清单、样例数据等在版本及附属资料设计中承接，遵循 [代码规范](AiCollabHub-代码规范.md) 的“模块专属资料设计”；草稿随申请保存，正式资料关联具体版本，不能以待审或最新外部数据覆盖历史版本。质量评分由当前版本对应的审核结果或明确的工具链来源提供，不以用户星级推算，不增加一个可独立修改的主表评分副本。

## 场景应用主表 applications

业务定位：保存一个场景应用的稳定标识、当前正式展示资料、当前版本关联和启用状态。

| 字段名 | 中文名称 | 类型 | 业务逻辑 / 枚举值 / 备注 |
| --- | --- | --- | --- |
| `id` | 应用编号 | `uuid` | 主键；平台生成，版本更新时保持不变。 |
| `name` | 应用名称 | `varchar(200)` | 必填；用于列表、搜索和详情标题，不要求全局唯一。 |
| `english_name` | 英文名称 | `varchar(200)` | 可空。 |
| `summary` | 应用简介 | `text` | 必填；用于列表摘要和概览开头。 |
| `description_markdown` | 详细说明 | `text` | 保存 Markdown 正文；未提供时可空。 |
| `category` | 应用分类 | `varchar(64)` | 必填；按分类字典维护，当前有文档创作、会议办公等。 |
| `provider_name` | 提供单位 | `varchar(200)` | 必填；提供应用的单位名称。 |
| `contact` | 联系人 | `varchar(200)` | 可空；只保存联系人姓名。 |
| `development_team` | 开发团队 | `varchar(200)` | 可空；开发团队名称。 |
| `sharing_agreement` | 共享协议说明 | `text` | 可空；展示使用、共享方面的约定。 |
| `tags` | 关键词标签 | `jsonb` | 字符串数组，默认 `[]`；用于搜索、筛选和标签展示。 |
| `capabilities` | 能力说明 | `jsonb` | 字符串数组，默认 `[]`；对应现有概览的“能力标签”，与搜索关键词分开。 |
| `creator_id` | 创建人编号 | `uuid` | 关联 `users.id`；本地发布时必填，外部同步资源可空。 |
| `current_version_id` | 当前版本编号 | `uuid` | 关联应用版本记录；指向当前正式展示的版本，关联建立前可空。 |
| `status` | 状态 | `varchar(16)` | `enabled` 启用、`disabled` 禁用；默认 `disabled`，不表示审核状态。 |
| `created_at` | 创建时间 | `timestamptz` | 本平台创建这条主表记录的时间。 |
| `updated_at` | 更新时间 | `timestamptz` | 主表资料或启用状态发生变化时更新。 |

底层模型通过应用关联记录获取，支持一个或多个模型；主表不额外维护一份独立的模型名称。使用教程、调用参数、技术信息等遵循 [代码规范](AiCollabHub-代码规范.md) 的“模块专属资料设计”，按实际需要采用版本正文、结构化资料或子表，本次不定稿这些关联表的完整字段。

## 审核、版本与互动数据的归属

| 数据 | 归属 | 已确定的规则 |
| --- | --- | --- |
| 资源启用状态 | 两张主表各自的 `status` | `enabled`、`disabled`，默认禁用；不替代访问权限或外部服务可用性。 |
| 数据集当前审核状态 | `dataset_publications.review_status` | `pending` 待审核、`approved` 已通过、`rejected` 已驳回；草稿未进入审核时可为空。 |
| 应用当前审核状态 | `application_publications.review_status` | 与数据集采用相同含义；每次发布申请独立维护审核状态。 |
| 历次审核记录 | 共用 `resource_reviews` | 关联具体发布申请，记录每次审核人、结论、意见和时间；具体字段另行设计。 |
| 版本号与版本资料 | 对应版本记录 | 主表仅保留 `current_version_id`，版本表完整结构后续设计。 |
| 收藏、用户评价、关注 | 共用 `resource_favorites`、`resource_ratings`、`resource_follows` | 通过资源类型和稳定资源 UUID 关联；本次不修改其既有讨论边界。 |
| 收藏数、评价人数、平均评分 | 根据有效互动明细聚合 | 接口组合并可使用 Redis 缓存，主表不存汇总列；没有评分时返回空值。 |

审核通过与资源启用是不同动作。应用 V1 已启用时，V2 申请的 `review_status=pending` 不改变 V1 的公开资料和主表的 `status=enabled`。V2 审核通过并正式发布后，主表资料与 `current_version_id` 在同一事务中切换；已禁用的资源不会仅因审核通过就自动启用。

`current_version_id` 不仅要引用有效版本，还必须属于本条资源并已通过审核。关联建立前允许为空，启用时必须满足上述条件。实际约束随版本表一并实现，不能只验证一个版本编号存在。

## 后续设计边界

- 发布申请、版本、共用审核、应用关联及附属资料表仍需逐项设计；上述关联说明不代表已确定其全部字段或已实现流程。
- 模型库、知识库、AI 工具按各自实际详情页和接口来源确定字段，不照搬数据集或场景应用的专属列。
- 对接来源、同步规则与访问权限另外按明确需求设计。启用状态不能作为用户获得资源使用权限的依据。
- 本文件为主表定稿依据；2026-09-19 阶段草案中“主表只存版本号”“主表承接全部技术资料”等冲突内容不再用于这两张主表。历史实现和暂存重构在实际实施任务中处理。
